## 2. 范围界定

### 2.1 包含功能

- 管理员主动发放积分：向指定用户发放指定数量的积分，附带发放原因和可选有效期
- SDK 发放积分：第三方应用通过 SDK 向用户发放积分，附带原因和可选有效期
- 新增积分类型 `granted_credit`：专用于管理员和 SDK 主动发放的积分
- 发放交易记录：所有发放操作生成可追溯的交易记录（类型为"发放"）
- 前端管理员发放界面：在积分管理页面提供发放入口和表单

### 2.2 不包含功能 (Out of Scope)

- 批量发放（向多个用户同时发放积分）
- 活动系统/活动实体（无活动创建、管理、用户申领等独立概念）
- 积分发放审批流程
- 发放记录独立管理页面（复用现有交易历史）
- 发放积分回收/撤销
- 发放模板或定期发放规则

### 2.3 依赖项

- **积分系统核心**：复用积分账本、交易记录、消费优先级等核心功能；影响积分类型枚举、交易类型枚举
- **SDK 系统**：SDK 新增发放方法依赖现有 API Key 认证和权限模型
- **管理后台**：前端发放界面依赖现有积分管理页面和权限控制

## 3. 需求概述

### 3.1 功能描述

在现有积分系统中新增主动发放能力，使管理员和第三方应用（通过 SDK）能够向指定用户直接发放积分。发放时须附带原因描述，可选设置积分有效期。发放的积分属于新的 `granted_credit` 类型，遵循现有基于过期时间的消费优先级规则。

### 3.2 关键特性

- **管理员主动发放**：Realm Admin 可在管理后台向本 Realm 内任意用户发放积分
- **SDK 发放**：第三方应用通过 SDK 调用发放接口，用于实现积分奖励、等级提升等运营场景
- **新积分类型 granted_credit**：与现有 topup_credit、subscription_credit 等类型并列，语义清晰
- **可配置有效期**：发放时可指定有效期天数或设为永久有效
- **发放原因追溯**：每次发放必须附带原因描述，交易历史完整记录

## 4. 业务规则与状态

### 4.1 业务规则

**积分类型**：
- **发放积分（granted_credit）**：由管理员或 SDK 主动发放获得，可配置有效期（N 天有效或永久有效），遵循现有基于过期时间的消费优先级规则

**消费优先级**：
- 沿用现有按过期时间优先消费的规则（expires_at 升序，NULL 排最后）
- granted_credit 与其他类型积分混合后，按各自过期时间排序消费，不因类型而获得消费优先或靠后

**发放规则**：
- 积分数量必须大于 0
- 发放原因为必填项
- 有效期可选：指定天数（> 0）或永久有效（不设置）
- 管理员只能向本 Realm 内用户发放积分
- SDK 发放受 API Key 权限控制，遵循 Realm 隔离

**交易记录**：
- 发放操作生成交易记录，交易类型为"发放"（grant）
- 交易记录包含：用户 ID、积分类型（granted_credit）、金额、发放原因、过期时间、操作者标识
- 管理员发放记录操作者为管理员身份；SDK 发放记录操作者为 API Key / Client App 标识

### 4.2 关键状态与异常

- **用户不存在**：发放时目标用户不存在，返回明确错误，不创建交易记录
- **跨 Realm 操作**：管理员或 SDK 尝试向其他 Realm 的用户发放积分，返回权限不足错误
- **积分数量无效**：数量为 0 或负数，返回参数校验错误
- **缺少发放原因**：返回必填项校验错误
- **权限不足**：管理员不具备 `points.manage` 权限或 SDK 的 API Key 不具备积分发放权限，返回权限不足错误

## 5. 功能需求

### 5.1 核心需求

- 新增 granted_credit 积分类型，与现有 4 种类型并列
- 管理员发放接口：支持指定用户、积分数量、有效期（天数或永久）、发放原因
- SDK 发放方法：与现有 SDK 方法风格一致，支持指定用户、积分数量、有效期、发放原因
- 发放成功后创建交易记录（类型为 grant），更新用户积分余额
- 前端管理页面新增"发放积分"入口和表单（用户选择、数量输入、有效期设置、原因输入）
- 交易历史中"发放"类型记录可按现有筛选规则查看

### 5.2 验收目标

- 管理员能在管理后台向指定用户成功发放积分，积分正确到账
- 管理员可设置积分有效期，到期后积分正确过期
- SDK 能通过 API 向指定用户发放积分，返回发放结果
- 发放的积分类型为 granted_credit，在用户余额中按类型正确显示
- 发放交易的消费优先级遵循现有过期时间优先规则
- 所有发放操作生成可追溯的交易记录，包含发放原因
- 权限和 Realm 隔离正确：非本 Realm 用户不可发放，权限不足被拒绝
- 前端发放表单校验完整：数量 > 0、原因必填

## 6. API 相关约束

**适用性**: 适用

- 接口能力范围：管理员发放积分接口（管理端）、SDK 发放积分接口（外部 ext 端）
- 访问控制：管理员发放需 `points.manage` 权限；SDK 发放需 API Key 具备积分发放权限
- Realm 隔离：所有发放操作严格遵守 realm 数据边界，仅可发放给本 Realm 内用户
- SDK 发放方法与现有 SDK 风格一致：共享 Client 实例、统一错误类型
- 所有发放操作创建交易记录，交易类型为 `grant`
- API 兼容性：新增交易类型不影响现有客户端

---

## 7. 前端/交互约束

**适用性**: 适用

- 管理入口：在积分管理页面（或用户积分账户详情页）提供"发放积分"按钮
- 发放表单字段：用户选择（下拉搜索）、积分数量（正整数）、有效期（天数输入或"永久有效"选项）、发放原因（文本输入）
- 发放确认：提交前显示确认弹窗，包含发放摘要（用户、数量、有效期），需管理员二次确认
- 状态反馈：发放成功显示成功消息和更新后的用户余额；失败显示具体错误信息
- 交易历史：发放记录在现有交易历史中以"发放"类型显示，可按类型筛选查看

---

## 8. 已确认决策

- 不创建独立的活动/活动实体，直接发放积分并附带原因
- 新增 granted_credit 积分类型，与现有类型并列
- 消费优先级沿用现有基于过期时间的规则，granted_credit 不因类型获得特殊优先级
- 发放原因为必填项
- 有效期可选（天数或永久有效）
- SDK 发放方法与现有 SDK 风格一致
